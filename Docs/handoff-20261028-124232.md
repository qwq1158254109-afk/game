## 本轮最重要的四条经验

### 1. 编译错误会让 Unity 以 SAFE MODE 启动
症状：进程在、`ensure_unity.ps1` 报 `TIMEOUT`（300s 端口不开）。
判定：进程 `MainWindowTitle` 含 `SAFE MODE`；`grep "error CS" %LOCALAPPDATA%\Unity\Editor\Editor.log`。
处置：修编译错误 → 关 Unity → 重启。

### 2. 桥的 `recompile` 经常不触发 domain reload
判据：`unity_cmd.py ping` 的 `armedAt` 不变，且 `Library/ScriptAssemblies/*.dll` 的 mtime 没更新。
可靠做法：`recompile` → `sleep 40` → 查 dll mtime。MCP `recompile_scripts` 能真正编译并返回错误列表，但常 60s 队列超时（超时不代表没执行，事后查 dll mtime 更准）。
**本次最后一次改动（跑批器加 TestCase 支持）始终没编译上，是环境问题不是代码问题。**

### 3. `Application.CanStreamedLevelBeLoaded` 在编辑器非运行态恒为 false
这把「场景已配置」的判定全部打成 `Disabled`，是 5 条场景路由测试长期红的真因之一。
现在 `LocationSceneRouter.CanLoadScene` 在 `!Application.isPlaying` 时直接放行。

### 4. batchmode 全量回归这次起不来
`Unity.exe -batchmode -nographics -runTests` 启动 5s 后自退，日志停在脚本编译阶段（`Duplicate assembly ...` 之后）。清 `Temp/UnityLockfile` 无效。
替代方案：临时 Editor 菜单 + 反射跑批器（`Tools/Temp/Run ALL EditMode Tests`，本轮已删）。**注意它不展开 `[TestCase]`**，会漏 5 个类约 98 条；本轮用「这 5 个类基线 109 条全 Passed + 未改动」补齐论证。
