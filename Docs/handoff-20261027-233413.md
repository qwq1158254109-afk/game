### 三条用户需求的结论

**1. 商店格子里的黄条 —— 根因是贴图，不是 UI 元素**

`button_normal.png`（64×24 木牌）第 7 行本身就是 `(226,178,76)` 金色高光线。九宫格 `border=5`，y=5..18 属于**可拉伸区**，372×162 的格子里这 1px 被纵向拉成约 10px 的粗黄带。按钮只有 46 高，同一行只拉成 2px，所以以前没暴露。
悬停态同理：`button_hover.png` 的 y=5 近白高光 + y=7 浅黄线，在格子里变成两条亮条。

→ 做法：**不动全局贴图**（按钮上那条细高光还在），只给商店格子新增两张 flat 变体，`ForceStockBackground` 优先 `Resources.Load`，找不到才退回主题原图并打警告。

**2. 关闭商店 → 回售货员菜单**

售货员交互点已确认挂的是 `Dialogue_npc_shop_owner_Menu.asset` + `npc_shop_owner.asset`（`ShopMapScene.unity` 的 `action_shop_browse_goods` 节点，guid `f134aa7c…` / `1297ec43…`）。菜单第 3 项 `openShop: 1`。
→ `MapShopView.Hide()` 用 `wasVisible` 保护，只在面板确实可见时触发回调，初始收起和活动路径打开都不会误触发。

**3. 送礼 / 打招呼 → 回对话栏**

- 送礼：`giftReturnDialogue` 在 `HandleOptionChosen` 的 `chooseItemAsGift` 分支记录（此时 `currentDialogueData` 还是菜单）
- 打招呼等子对话：`jumpReturnDialogue` 记录在**奖励检查之前**（纯分支选项没有 rewards，摆在后面会提前 return 漏掉）
- **两条都防了自我循环**：`Play` 会重写 `pendingComplete`，回菜单前必须先把原回调抓到局部变量，否则菜单播完又绕回收尾逻辑

### 踩过的坑（本轮新增）

1. **EditMode 测试里 `AddComponent` 不跑 `Awake`** —— `DialogueView.panelRoot` 一直是 null，`SetVisible` 什么都做不了，面板永远"关不掉"，断言 `activeSelf` 全错。测试里必须手动 `view.panelRoot = viewObject`。
2. **EditMode 里任何 Sfx 播放都会炸** —— `SfxPlayer.PlayInternal` 发现实例为 null 就 `Bootstrap()`，而 `Bootstrap` 里的 `DontDestroyOnLoad` 在编辑模式下抛 `InvalidOperationException`，把整条被测流程打断（表现为 `TargetInvocationException` 包一层）。修法是反射塞一个**没调过 `Build()`** 的实例（`sources` 为 null 时 `PlayInternal` 直接 return）。
3. **Unity 开着时 batchmode 编译不了**（"另一个正在运行的 Unity 实例打开了此项目"），`MSBuild.exe` / `dotnet build` 在本机被安全策略拦（LOLBin 黑名单），`dotnet` 只有 runtime 没有 SDK。**唯一可行的编译闸门是让用户在编辑器里 Ctrl+R，然后读 `Library/Bee/tundra.log.json`**（`python Tools/extract_compile_errors.py`）。
4. 确认新代码真进了程序集的办法：`grep` 二进制找符号（`Library/ScriptAssemblies/StudentGrowth.Runtime.dll`）。`private const string` 会被内联，搜不到常量字符串属正常。
