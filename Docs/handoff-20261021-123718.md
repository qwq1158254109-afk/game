## 1. 本轮做了什么（按时间顺序）

### 1.1 房间壳照「最新版学校壳」重做

用户最初说"照初版"，后更正为"**最新版**"。查实：**git 里没有"最新版的家"**——家资源只在初版
`900848a` 进过 git（327 文件），之后 4 个提交家相关文件 **0 个**，所有改动都在工作区未提交。

用模板匹配钉死来源（`Tools/probe_floor_provenance.py`）：用户截图的地板小块在
`Assets/Art/New2_0/School/Source/SchoolShell.png` 上 **MAD=4.66**（最小），
`home_new_space.png` 是 9.44 → **地板/墙照学校壳做**。

`Tools/make_shell_tex.py` 取源全换成 SchoolShell，按它的四段节奏组装墙带：

| 段 | 高 | 生成值 | 学校实测 |
| --- | --- | --- | --- |
| 奶油墙面 | 62 | L=162.7 R-B=75.4 | 163.8 / 74.9 |
| 深木护墙板 | 40 | L=57.4 R-B=47.0 | 57.8 / 46.9 |
| 地板 | — | L=101.1 R-B=93.4 | 101.3 / 93.1 |

**护墙板是新增段落**——之前家墙带根本没有护墙板，这是"照学校做"最明显的缺失。

### 1.2 方案B：四墙等厚加厚到 2.5 单位

### 1.3 门素材"奶油墙"污染（用户报"左右两扇门重叠"）

门素材 `home_ref_exit_door.png` x0..23 是**奶油墙**（RGB(183,132,85) 饱和 0.55），
`crop(22,0,150,125)` 仍带 7.8% 墙色，放大到 160 后成左边缘+底边一圈；
侧墙门 `ROTATE_90` 后这圈墙色**横躺在房间地板上**。

修法 `_neutralize_wall_pixels()`：**饱和≥0.42 且 L≥110** 判墙 → 换门框深木 (91,48,21)。
降到 **2.54%**。**窗玻璃饱和只有 0.40，所以必须用饱和度判、不能只用亮度**。

### 1.4 旧输入刷屏（33 万条报错）

`activeInputHandler: 1`（只用新 Input System），但 9 个脚本仍调旧 `UnityEngine.Input`。
刷屏主源 `InventoryController.cs:67`（`Update` 里 3 处裸调用、**完全无 try/catch**），
`Editor.log` 累计 **335593 条**。

方案 A：9 个文件全部补上「抛一次就置 `legacyInputBlocked`、之后只走新输入」守卫。
其中 `CardChoiceView` / `MapInteractionConfirmView` 的 `Pressed` 是**静态方法**，标志必须 `static`。

### 1.5 交互提示栏"交互后一直存在"

真因：`IsCompleted(target)` 对门恒 false、对可重复交互点位 `maxUses=-1` 也 false
→ 结果提示 2.2s 后进 `Nearby` → `ShowTarget()` 又把行动提示显示回来。

修法：新增 `suppressPromptTarget` + `SuppressPromptFor()` / `ClearPromptSuppression()`。
交互过的目标**人没走就保持隐藏**，走开再回来才重新显示。

**探针实测通过**：

```
t7-t11   Nearby      alpha=1.00  "按 E：早点休息｜消耗 1 时间｜精力 +20｜压力 -5"
INTERACT -> True
t12-t19  Confirming  "确认执行：早点休息。"
CONFIRM  -> Completed
t20      Completed   alpha=1.00  "完成活动：早点休息。休息已结束。"
t21 起   Nearby      active=False  alpha=0.00  text=""     ← 已淡出并保持
```

### 1.6 三个真 bug（"走到门上没反应"）

**(a) 侧墙被算成没有门洞**：`apply_room_thickness.py` 把侧墙两段写成 `cy=±4.0 / h=8.0`，
合起来 `y[-8,8]` —— **完全没留门洞，门被墙堵死**。已由 `Tools/fix_wall_specs.py` 修（14 处）。

**(b) 房间门触发区埋在墙里**（最终根因）：`HomeRoomsBuilder.DoorWallCenter()` 把触发区
放在墙体中心 `x=±14.305 / y=8.0`，而玩家边界是 `±12.155 / ±5.85` → **差 2.15 单位，
玩家永远走不进触发区**。门是 `RoomDoor`（`OnTriggerEnter2D` 自动切场景，**不是按 E**）。

修法：新增 `DoorTriggerCenter()`，**触发区与门面分离**：

```csharp
// 触发区：可走区内侧
float limit = InnerHalfW - PlayerMargin;   // 12.155
float x = limit - triggerSize.x * .5f;     // 11.705

// 门面：仍贴进墙洞（视觉正确）
Vector3 localOffset = wallCenter - triggerCenter;
```

**(c) 场景重建在 Play 模式下静默失败**：`BuildRoom` 用 `EditorSceneManager.OpenScene`，
Play 模式抛 `InvalidOperationException: This cannot be used during play mode`。
**菜单仍返回"成功"，只有 `Logs/mcp-task.log` 里有真相**。

### 1.7 插件"看不到"

四个 git 依赖（LitMotion / UIEffect / NavMeshPlus / YarnSpinner）**都装好了**
（`Library/PackageCache/` 四个目录都在、`packages-lock.json` 全部解析）。

不在 **My Assets**（那里只显示 Asset Store 资源）、也不在 Unity Registry，
只在 **"Packages: In Project"**。

## 5. 环境事实（本轮新踩的，已并入 AGENTS.md 20.4）

1. **进 Play 加载的是 Build Settings 第 0 个场景（`MainMenuScene`）**，不是编辑器里打开的场景。
   要测房间必须游戏内进入，或让探针自己 `SceneManager.LoadScene("HomeXxxScene")`。
2. **运行时验证必须走落盘探针**：进 Play 的域重载**必然**把 MCP 打半残
   （本次会话复现 4 次，8096 出现大量 `CLOSE_WAIT`）。
3. **`PlayerFacingInteractor.targets` 在编辑器里为空数组是正常的**（运行时由
   `FullscreenMapSceneController.WireInteractionSystem()` 填充）。
4. **客厅只有 2 个交互目标**（`FamilyNpcObject` + `ExitDoorObject`）：
   客厅家具都是纯装饰 `DecorSpec`。可交互家具在卧室/书房。
5. **`Editor.log` 只写一句 `All compiler errors have to be fixed...`**，不含文件名行号；
   明细只在 `Library/Bee/tundra.log.json`，用 `python Tools/extract_compile_errors.py` 读。
6. **Unity 只在窗口重获焦点时才扫外部文件改动**，终端里改完不会自动重编译。
7. **不要为反射随手加 `using System;`**：`InventoryController` 原有三处
   `Object.FindAnyObjectByType<T>()`，加后 `Object` 歧义 → 3 条 CS0104、Play 直接进不去。
   修法是**去掉 `using System;` 改全限定名**。
8. **`Build Home Room Scenes` 必须在 Edit mode 下执行**，Play 模式下
   `EditorSceneManager.OpenScene` 抛异常，**菜单仍返回"成功"**。
