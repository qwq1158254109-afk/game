### 1.1 各自根因（复用时先看这里）

- **体检误报**：`ContentHealthAudit.BuildSceneWiringIndex()` 只用阶段地图登记的 6 个 sceneName 建「场景→地点」表；家卧室/书房/厨房是靠 `RoomDoor` 切场景的子场景，未登记 → 归不到地点 → 被渲染成「未接线」。修复=扫描时收 `RoomDoor.targetSceneName`，从已登记场景 BFS 扩散；归不到地点的场景改写到报告第 1 节 ⚠ 行。
- **启动链**：`SaveContentCatalog.asset` 前 3 条指向 `0715da6` 删掉的旧活动资产（`Assets/Data/StudentGrowth/HomeMap/Home{DeskPlan,FamilyDinner,RestEarlySleep}.asset`）→ 解析 null → `RegisterAsset` 抛 `SAVE_CATALOG_INVALID` → `GameApplicationRuntime.Awake`（`GameApplicationRuntime.cs:72`）中断 → `Coordinator` 全空 → 主菜单按钮每次 NRE。修复=清目录（17→14 条）+ `CreateRuntime` 跳过陈旧条目并告警 + `MainMenuController` 加 `IsReady` 守卫。
- **学校过道**：玩家胶囊 0.45×0.72（`RpgPlayerController.cs:345`），课桌 1.584×0.769、椅子 0.903×0.497；排间净空 0.797/0.839/0.859 → 余量 7.7cm 转不过弯。修复=24 个碰撞体只改 `m_Size.y`/`m_Offset.y`，净空变 1.10/1.15/1.16。

## 2. 环境事实（本轮新踩到的，优先于旧文档）

1. **MCP 端口口径不一致**：`ProjectSettings/McpUnitySettings.json` 里是 **8095**，而 `AGENTS.md 20.4` 写的是 8096。本轮 MCP 全程不可用（`get_play_mode_status` 排队 60s 超时；日志刷 `Failed to start WebSocket server: Port 8095 is already in use`）。**不要反复重试**，直接改用下面的验证路径。
2. **不走 MCP 的验证路径（本轮全程在用，稳定）**：
   - 编译/跑编辑器方法：`Unity.exe -batchmode -quit -projectPath "E:\大创项目" -executeMethod <类.静态方法> -logFile Logs\xxx.log`，用 PowerShell `Register-ScheduledTask` 启动（脱离进程树），约 20–30 秒跑完。跑前后备份/恢复 `Library/LastSceneManagerSetup.txt`（批处理会清空「上次打开的场景」）。
   - 编辑器开着（尤其 Play 中）时**无法批处理**——工程锁被占。此时只能读 `%LOCALAPPDATA%\Unity\Editor\Editor.log`：`grep -c "error CS"` 判编译，`grep "Loaded scene"` 判场景跳转。
   - 编译是否真的发生过：比 `Library/ScriptAssemblies/*.dll` 与源文件的 mtime（运行时改动看 `StudentGrowth.Runtime.dll`，编辑器脚本看 `Assembly-CSharp-Editor.dll`）。
3. **`tasklist` 里多个 `Unity.exe` ≠ 多个编辑器**：除主进程外，标题为 exe 全路径、内存 ~80MB–1GB 的是 AssetImportWorker。判主进程看内存（>1GB）与窗口标题。
4. **生成器覆盖警告**：学校场景由 `Assets/Editor/StudentGrowth/SchoolMapSceneBuilder.cs` 生成（菜单 `Tools/Student Growth/School/Rebuild Editable School Map`），家四房间由 `HomeRoomsBuilder.cs` 生成。**手改场景必须同步改构建器**，否则下次重建回退（本轮两处都同步了）。
