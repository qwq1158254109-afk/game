## 6. 三个踩过的坑（重要）

1. **去光照梯度必须逐通道重新锚定。**
   写成 `reg / bg * bg.mean()` 时，`bg.mean()` 是三通道总均值（**标量**），会把每个通道都拉到同一个灰度值。实测地板 R−B 从 **125 掉到 0.1**，整块变灰。
   正确：`reg / bg * bg.mean(axis=(0,1))`。

2. **无缝化用镜像半条，不要用 `np.roll` + 交叉淡化。**
   `np.roll` 把对侧边缘像素循环过来，制造硬跳变——实测接缝 **26.7**（内部基准 1.03）。
   镜像法 `|左半 左半镜像|` 实测接缝 **0.00**。

3. **墙面材质要取整段再压到目标高度。**
   只截最亮的顶部 64px（均值 166.4）会让墙整体偏亮、读起来「发飘」。
   取整段 195px 压到 64px，保住 y77→y257 的 166→136 渐变。

另外：**探针取样区必须先自检**。第一版把 x 250..700 当「净面」，实际 x 275..410 就是一扇窗，镜像后变成「每 450px 一扇窗」。现在脚本里有 `check_no_glass()`，偏冷率必须为 0 才继续。

用户要的「源图的地板」不是颜色（颜色本来就一样：源图 `[177.8 105.5 51.7]` vs 砖 `[178.3 105.8 51.6]`），

**修法**：新增 `floor_light_profile()` + `apply_floor_light()`，把源图地板的光照拟合后铺到房间地板区。

关键：**不能逐行照抄源图亮度**。那里面混着楼梯、厨房隔墙、家具投影等内容起伏，
照抄会留下尖峰与骤降（实测 y780 尖峰 +7、y900 骤降 −22.7）。
改为**低阶多项式拟趋势 + 宽高斯强化中部**，得到光滑曲线。

成品实测：贴北墙 86.8 → 中部 131.0 → 贴南墙 88.9，最大相邻跳变 **7.9**（原为 −22.7）。

另修：地板砖原先纵向也做镜像，与光照曲线相撞出现横向色带（y≈600）。

### 10.1 真根因：墙砖按「整块起点」跳过，造出一个整块大小的缺口

**这是本轮最严重的 bug，也是用户看到的「空隙」的真正来源。**

旧逻辑：

```python
x = 0
while x < CANVAS_W:
    if not any(g0 <= x < g0 + g1 for g0, g1 in gaps):   # 只看这一块的起点
        canvas.alpha_composite(band..., (x, y0))
```

南墙门洞是 `(848, 128)` → 洞 848..976。墙砖宽 240，块边界落在 0/240/480/720/960/1200。
块 **x=960 覆盖 960..1200，起点 960 落在洞里 → 整块 240px 被跳过**，

**修法**：新增 `_gap_runs()`，逐像素求补集，只挖掉真正的洞口；再按连续区间铺砖（`_tile_runs_h/_v`）。

侧墙带原先通铺整个画布高度（0..1056），压到南/北墙带上；南墙带又只铺到 `x=CANVAS_W`。

**修法**：
- 地板只铺**可走区**（`y 96..960`，`x 96..1728`）
- 北/南墙带只铺 `x 0..CANVAS_W-W_SIDE`
- 侧墙带只铺 `y W_TOP..CANVAS_H-W_TOP`
- 东北 / 东南两个角用竖墙带补 96×96 方块

**结构因此变干净了**：可走区 = 地板区 = 世界 `-12.75..12.75 × -6.75..6.75`（25.5×13.5），
与 `HomeRoomsBuilder` 的碰撞体完全一致。

- 门洞统一 128（沿墙）× 96（墙厚方向），四面一致。

## 11. 第三轮修复：补回墙脚阴影（AO）

用户：「底图缺少了阴影效果」。

**这个阴影是我上一轮亲手弄丢的。** 当时为了消除地板上的横向色带，
我把源图里墙脚那段亮度骤降当成「楼梯/厨房隔墙的内容起伏」削掉了
（记录在 §9.2：实测 y900 骤降 −22.7）。

实际那是**真实的环境光遮蔽**，是地图「有体积」的关键。

### 11.1 源图实测的阴影参数

| 位置 | 贴墙亮度 | 无遮蔽亮度 | 深度 | 恢复距离 |
|---|---|---|---|---|
| 北墙脚（源图 y298 起） | 66.9 | 89.5 | **−25%** | ~70px |
| 南墙脚（源图 y966 起） | 约 44 | 93 | **−53%** | ~70px |
| 左墙脚（源图 x96 起） | 68.7 | 86.8 | **−21%** | ~90px |

### 11.2 为什么用解析式而不是逐行采样源图剖面

先写的是「逐行采样源图剖面 → 前缀最大值单调化 → 铺到地板」，
**连续失败三次**，每次原因都不同、都写进注释了：

1. **方向错**：`np.minimum.accumulate` 得到递减序列，把剖面压平。
2. **归一化基准错**：用区间最大值归一。南端贴墙处存在比远端更亮的像素
   （门槛/地垫亮边 103 > 远端 91），前缀最大值在索引 0 就锁死 → 整条常数。
3. **窗口末端不是无遮蔽地板**：改用远端值归一后又发现，
   窗口末端恰好落在阴影核心上（57.4），于是 normalized[0] = 1.62 成为最大值，
   再次锁死 → 整条常数。

根因：**源图南端叠了门槛、地垫、台阶三层结构**，逐行采样无法区分
「哪里有遮蔽」和「那里本来是什么材质」。

**最终做法**：只保留「贴墙暗多少 + 多远恢复」两个**可测参数**，
衰减形态用标准 AO 指数式：

```python
def edge(dist, depth):
    return 1.0 - depth * np.exp(-dist / decay)
```

四个方向各取一条曲线，按 `min(纵向, 横向)` 合成二维场。

南端深度取 **0.40** 而非实测的 0.53：源图那 53% 里混了门洞内凹的投影，
而我们的墙紧贴画布外沿、没有内凹，照搬会过重。

## 12. 第四轮：墙加厚到 2.0 单位，门同步

用户：「把墙弄高一些，门也同步」。

俯视布局里**墙带的竖向高度就是墙厚**，所以"弄高"= 加厚。

### 12.1 取舍与选择

```

1.5 + 13.5 + 1.5 = 16.5  ->  2.0 + 13.5 + 2.0 = 17.5   (高)
```
