## 完成内容

### P2-01：显式版本、编译定义与实例

- `ChallengeData.battleRulesVersion`：Legacy=0、Unified=1；另有 Unified 专用手牌上限、意图模式及显式 fallback。
- `CardData.effectSchemaVersion`：Legacy=0、Unified=1；与挑战版本完全独立，旧数据缺省仍为 Legacy。
- `BattleCompiler` 在开战前验证并冻结定义；同一个 CardData 可以在牌组中重复出现，不同资产占用同一定义 ID 会报错。
- 旧 `damage`／`drawCount` 不叠加进 effects；旧 block 和 Rest／Self 隐式格挡编译成明确效果。Unified 仅执行规范 effects，不再隐式补格挡。
- `CardInstance` 快照包含实例 ID、定义、所在牌堆、本回合费用差；真实内部牌堆只由 Engine 改动，UI 得到只读快照。
- 新效果枚举追加到原枚举末尾，未重排旧枚举数值。

### P2-02：规则内核与牌堆

`BattleEngine` 是同步规则对象，不查找场景、不调用 UI／协程／系统时间／全局随机。它从 Controller 接收已准备定义、长期状态基线、现有运行会话 ID、场次 ID 和随机源。

Draw、Hand、Resolving、Discard、Exhaust 的迁移集中在 `MoveCard`。出牌先从 Hand 移到 Resolving，执行效果后归位；只有 Draw 空时才把 Discard 洗回，Resolving 与 Exhaust 不回流。实例总数在行动后检查守恒。

`ChallengeController` 保留旧公共接口，新建 partial 实例接口。P2 启动后旧 CardData 出牌／回合／结果入口不能同时写这场战斗；旧战斗未结束时也不能启动新内核演练。新格式／新挑战规则在 P1 校验器中明确阻断，防止被旧 Resolver 误读。

### P2-03：行动、回合、伤害及故障

请求携带 runtimeSessionId、battleId、expectedRevision、requestId、instanceId、targetId。非法请求不扣费、不移牌、不增加 revision、不消耗随机数。已处理 requestId 返回 AlreadyHandled，不能把重复结束回合变成下一轮结束。

Controller 使用既有 GameSessionLifetime.Matches 检查当前会话，另有 presentationBusy 门禁。旧会话迟到回调不会重新创建应用单例或影响新战斗。

完整卡牌收尾后才判断胜利；耐力归零立即停止后续数值效果，败北优先。最后回合仍可出牌达标；结束按钮在尚未达标时直接 TurnLimit，不再执行敌方行动。最后回合的意图预览与界面提示也遵守此规则。

多段伤害按段扣格挡。Ethereal 优先于 Retain；所有实例的本回合费用差在正常回合收尾时清除。执行异常产生 Faulted 结果，归位 Resolving 中的牌，禁止继续规则输入，且没有正常奖励提交。

### P2-04：预览、随机及临时费用

- 洗牌使用注入的 `IBattleRandom`，默认 `xorshift32-v1`；记录种子和抽取位置，不使用 UnityEngine.Random。
- 预览在独立随机源副本和状态副本上运行同一规范效果。反复打开 Tooltip／预览不改变真实状态和抽牌顺序。
- 卡面使用实例费用、可用性及实际变化预览；Tooltip 同时显示编译规则和本次实际变化。Unified 进度接近目标时，预览显示钳制后的增量。
- 临时费用只写指定实例。两张同定义卡可分别为 0 费与 4 费，且旧 CardData.cost 不变。

### P2-05：关联属性副本与迁移样例

`LegacyEffectState` 直接复制 PlayerState 当前字段，再复用原 AddStat／ClampAll 的逐步语义。上限和当前值一起保留，每一步钳制顺序与旧代码一致；结果携带只读最终快照和实际变化记录，未按属性差值写回真实状态。

例如先把长期体力上限从 60 提到 80，再恢复体力至 80，副本终值为 80／80；真实 PlayerState 仍为 60／60。连续增加至上限再减少也按原顺序计算。

开局被动按现有 OnBossStart／OnBattleStart 时机编译，变化记录保留 itemId。当前被动不消耗库存；没有新增主动战斗道具使用入口，也不会在演练中调用旧道具 Resolver 去写真实状态。

迁移样例位于 `Assets/Resources/StudentGrowth/Battle/P2`：7 张现有卡牌和“课堂小测”1 个挑战，见 [migration.tsv](migration.tsv)。

| 资产 | 效果格式／规则 | 迁移说明 |
|---|---|---|
| 数学练习、模拟考试 | Unified 卡牌格式 | 保留原费用与推进值，显式单目标；标量只作迁移信息，不重复执行。 |
| 课堂专注、背单词、整理错题、课后复盘、好好睡觉 | Legacy 卡牌格式 | 保留既有推进、格挡和长期效果语义。 |
| 课堂小测 | Legacy 挑战规则 | 保留先被动后抽牌、无限手牌、超额进度、既有回合上限及意图兼容行为。 |

没有通过单张卡的格式迁移改变整场规则，也没有新增平衡数值。Unified 挑战的顺序／容量／意图通过专门测试数据验证。

原 CardData／ChallengeData 合写在 DataDefinitions.cs；直接创建持久资产缺少有效 MonoScript 引用。本批新增独立文件的 `BattleCardAsset : CardData` 与 `BattleChallengeAsset : ChallengeData`，只供新迁移资产使用。未移动原类、改旧 GUID 或改旧场景引用。Play 验证已确认域重载后资产仍可加载且脚本引用有效。

### P2-06：真实卡牌视图适配

实例界面调用原 `CreateCardButton`，继续使用 BattleCardView 与 HandLayoutController，并接入 P1 Sprite 配置。CardData 只保留为美术来源；新输入从视图保存的实例绑定、场次和 revision 发起，不通过卡名、索引或 CardData 反查实例。

验收实际反转手牌显示顺序后重建，并执行：免费实例 A 点击、费用不足实例 B 点击、旧视图回调、B 降为 2 费后的取消拖拽和命中目标拖拽、结束回合费用重置。每一步均核对实际实例 ID、费用、牌堆和 revision。

## 使用方式与测试步骤

Unity 菜单：`Tools > Student Growth > Battle > P2`。

1. `Open isolated interactive sandbox`：进入可手动操作的演练。可点击／拖拽卡牌、改变首张费用、结束回合和退出演练；结束手动查看时停止 Play。
2. `Verify instance UI in Play Mode`：自动执行实例 UI 验收，使用独立临时存档，结束后自动退出 Play 并恢复原 Game View 分辨率选择。
3. `Run rule regression`：运行 81 项相关测试，结果写入本目录。
4. `Create migrated sandbox content`：重新生成本批迁移样例。会按迁移定义重写这些样例的内容，手工调整样例前先更新该工具或另建资产。
5. `Audit migrated content`：只读检查现有样例，输出带资产路径和字段诊断的 [配置报告](content-audit.txt)。打开演练时保留已有配置；只有首次缺少必要样例时才自动创建。

启动演练／自动 Play 验收前，当前场景必须没有未保存修改且没有其他隔离测试运行。不会自动保存或替换用户场景。

## 注意事项与 P3 接续

正式旧 Boss 入口继续使用 P1；新 Engine 没有发奖、推进阶段或提交长期状态的调用，演练存档被明确阻止。旧永久牌组及 SaveGameCodec 格式保持不变。

P3 下一步应接通活动／Boss 来源上下文、成本凭证、关联属性整体提交、同一个 P1 消费者的去重与恢复、返回流程，然后再切换正式入口并重跑实例 UI 回归。普通地图战启动链没有在本批补齐。

未实现 P4 专注／分心／脆弱状态、指定弃牌／消耗选择、状态牌生成、下一张牌增强、持续能力 Active 区、多目标或 X 费；配置会报告不支持。未引入跨崩溃事务恢复、存档迁移或回放产品。

本批验证覆盖规则、真实演练视图和原 P1 战斗；没有运行发布构建，也没有宣称所有地图、所有存档恢复入口和场景切换全面验收完成。最终 Unity 状态见 [editor-final.txt](editor-final.txt)。
