# 美术风格规范（Art Style Guide）

> 版本 v1.0 ｜ 2026-10-26 ｜ 适用：本项目全部 2D 视觉资源
> 本项目像素风学生成长 RPG。本规范分「强制」与「建议」两级，**强制项应当能用脚本检查**。

---

## 0. 一句话基准

**暖棕米黄纸质 UI + 32×32 像素角色 + 48×48 透明底图标；全项目统一 Point 过滤、无压缩、单一精灵模式。**

---

## 1. 为什么需要这份规范

以下三组数字全部是 2026-10-26 对现有资产的实测结果，不是设计主张。

### 1.1 两套色板互不相干

| 用途 | 主色 | 占比 |
| --- | --- | ---: |
| UI 面板 `panel_paper` | `#F0D9A5` 米黄 | 74.5% |
| UI 描边 | `#342216` 深棕 | 15.0% |
| 图标底板 `icon_item_*` | `#1E332C` 深墨绿 | 58.1–80.8% |
| 图标描边 | `#7AA889` 青绿 | 9.4–14.0% |

图标主色与 UI 主色相差约 120° 色相（青绿 155° vs 暖棕 35°）。且图标有 **58–81% 的像素是底板**，贴到米黄纸纹上就是一块绿补丁。

### 1.2 有效分辨率被底板吃掉一半

逐像素测量「物件本体」（排除底板与描边）的实际占位：

| 画布 | 物件本体 | 面积占比 |
| --- | --- | ---: |
| 道具图标 48×48 | 约 28×28 | 30–40% |
| 属性图标 32×32 | 约 17×17 | 20–30% |

也就是说 48×48 是名义值，真正画东西的只有 28×28；放进 UI 按 64 显示就是 2.3 倍非整数放大。

### 1.3 导入设置错误（比画风问题更根本）

扫描全部 `.png.meta` 的实测分布（2026-10-26）：

| 目录 | 总数 | 配置分布 | 判定 |
| --- | ---: | --- | --- |
| `Art/Pixel/Icons` | 23 | **23× 双线性 / PPU 100 / 多切片 / 有压缩** | 全错 |
| `Art/Pixel/Backgrounds` | 22 | 9× 双线性+压缩+多切片；6× Point 但多切片；4× PPU 16 Single；3× PPU 64 Single | 9 张全错，6 张模式错 |
| `Art/Modern_Interiors` | **745** | **741× 双线性 / PPU 100 / 多切片 / 有压缩** | **几乎全错** |
| `Art/New2_0` | 336 | 176× PPU 16 Single ✓；**146× PPU 64 Single**；14× PPU 100 多切片 | PPU 三种并存 |
| `Art/Pixel/UI_New` | 32 | 28× Point / PPU 16 / Single / 无压缩 ✓ | 基本正确 |
| `Art/New2_0/Characters` | 45 | 43× Point / PPU 16 / Single / 无压缩 ✓ | 基本正确 |
| `Art/CardReferences` | 55 | 50× Point / PPU 100 / Single / 无压缩 ✓ | 基本正确 |

两个要点：

1. **双线性过滤 + 有损压缩**（`filterMode=1` / `textureCompression=1`）会让像素边缘灰化、色板偏移并产生杂色。图标 23 张与第三方瓦片 741 张都踩了这个坑，**这是图标发糊的直接原因，改配置即可改善，不必重画**。
2. **`New2_0` 里 PPU 16 与 PPU 64 混用**（176 : 146）。同一场景里两种像素密度并存，会让不同贴图的"一个像素"在屏幕上大小不一致——这是画面看起来不齐整的隐藏原因，且**比色板问题更难被察觉**。

## 2. 全局基准

### 2.1 PPU（Pixels Per Unit）

| 资源类型 | PPU | 说明 |
| --- | ---: | --- |
| 角色行走帧、家具、瓦片 | **16** | 项目既有基准，`pink_player_down_0` 与 `panel_paper` 都是 16 |
| UI 图标、UI 面板 | **16**（新建） | 存量图标为 100，见下方迁移说明 |
| 卡面 | 100 | 卡面只经 UI Image 显示，PPU 不参与世界尺寸计算 |

> **存量迁移（建议，非强制）**：UI 类资源走 `Image` 渲染，PPU 不影响显示尺寸，只影响 `SetNativeSize()`。因此 `Pixel/Icons` 的 PPU=100 **可以暂不改**，优先只改 filterMode 与压缩。若某天统一到 16，必须先确认该图没有被 `SpriteRenderer` 使用。

### 2.2 导入设置（强制）

所有像素资源必须满足：

| 设置 | 值 | 理由 |
| --- | --- | --- |
| Texture Type | Sprite (2D and UI) | — |
| Sprite Mode | **Single** | 多切片模式需要显式切图定义，单图用 Multiple 是配置错误 |
| Filter Mode | **Point (no filter)** | 双线性会让像素边缘发灰 |
| Compression | **None** | 有损压缩会让色板偏移、产生杂色 |
| Generate Mip Maps | **关闭** | 2D 像素图不需要 |
| Wrap Mode | Clamp | 防止边缘采样越界 |
| Max Size | ≥ 原图边长 | 否则会被降采样 |

### 2.3 像素对齐

- 所有精灵在场景中的位置必须落在**整数像素**上，坐标为 `1/16` 的整数倍
- 摄像机 orthographic size 与画布分辨率必须满足整数缩放，禁止出现 1.37 倍这类非整数比例
- UI Canvas 参考分辨率固定 **1920×1080**（`CanvasScaler.ScaleWithScreenSize`）
  - `Pixel/Icons` 的 1280×720 是历史遗留，任何新建 Canvas 都不得再用 1280

## 3. 色板

### 3.1 主色板（强制）

所有 UI 与图标只允许使用下表颜色，新增颜色必须先进本表再使用。

| 角色 | 色值 | 用量建议 |
| --- | --- | --- |
| 纸底亮 | `#F0D9A5` | 面板主体 60–80% |
| 纸底高光 | `#FFE5B8` | ≤ 10%，用于受光面 |
| 纸底暗部 | `#C59B64` | 10–20%，用于凹陷/阴影 |
| 描边深棕 | `#342216` | 轮廓线、文字 |
| 按钮深棕 | `#6D3E24` | 按钮底 |
| 按钮中棕 | `#9A6235` | 按钮高光面 |
| 强调金 | `#E2B24C` | 选中态、数值高亮，**≤ 8%** |
| 危险红 | `#B6483C` | 仅压力/警告 |
| 成功绿 | `#6F8F5A` | 仅正面反馈 |

### 3.2 语义色（强制，不可混用）

| 语义 | 色 | 出现位置 |
| --- | --- | --- |
| 压力上升 | `#B6483C` | 数值、警告框 |
| 心情上升 | `#E2B24C` | 数值 |
| 属性增益 | `#6F8F5A` | 结算清单 |
| 属性减益 | `#B6483C` | 结算清单 |
| 选中 | `#E2B24C` 底 + `#342216` 字 | 列表项、格子 |
| 不可用 | 原色 × 45% 不透明 | 按钮置灰、条件未满足 |

### 3.3 禁用（强制）

- ❌ 冷色系大色块（`#1E332C` / `#7AA889` 现有的图标底板配色）——与 UI 色相差 120°
- ❌ 纯黑 `#000000` 作描边——统一用 `#342216`
- ❌ 纯白 `#FFFFFF` 作填充——统一用 `#FFE5B8`
- ❌ 超过 8 色的渐变过渡——像素风靠色阶不靠渐变
- ❌ 半透明叠加超过 2 层——会产生不可控的混色

## 4. 图标

### 4.1 规格（强制）

| 项 | 值 |
| --- | --- |
| 画布 | **48×48**，四类图标统一（道具/属性/功能/状态） |
| 背景 | **完全透明**（alpha = 0），不允许底板 |
| 安全区 | 物件撑满 **40×40** 居中区域（四周留 4px） |
| 最小占位 | 物件包围盒 ≥ 36×36，即**占画布面积 ≥ 56%** |
| 描边 | **1px `#342216`**，只画外轮廓；内部结构不描边 |
| 色数 | ≤ 8（含描边与透明） |

**验收标准**：把图标缩到 **24×24** 仍能认出是什么。游戏内实际显示尺寸为 38–64px，这是唯一有意义的检验。

### 4.2 绘制规则（强制）

1. **一个图标只画一个物件**，不画场景、不画多个物体组合
2. **视角统一**：45° 俯视微斜（能看到顶面 + 正面），不混用正视与俯视
3. **光源统一**：左上受光，右下背光。高光放左上，暗部放右下
4. **不用纯色平涂**：每个物件至少 3 个色阶（亮面/中间调/暗面）
5. **不用抗锯齿**：边缘必须是硬像素，不允许半透明过渡
6. **冷色仅作点缀**：如饮料的液体、耳机的耳罩，面积 ≤ 画面 15%

### 4.3 语义重定（强制）

现有图标存在语义撞车与不可读，重做时按下表执行：

| ID | 现状问题 | 新语义 |
| --- | --- | --- |
| `icon_stat_social` | 画的是时钟，与 `icon_stat_time` 完全重样 | 两个并排的人头剪影 |
| `icon_stat_parent` | 画的是茶杯，与道具 `icon_item_warm_tea` 重样 | 大手牵小手 |
| `icon_item_exam_ticket` | 画成蝴蝶结，认不出 | 纸条 + 红色印章 |
| `icon_stat_chinese` | 方块 + 斜线，太抽象 | 摊开的书 + 笔 |
| `icon_stat_confidence` | 蓝圈内箭头，太抽象 | 竖起的大拇指 |
| `icon_stat_pressure` | 两个椭圆并排，认不出 | 头顶压着的重物 / 收紧的弹簧 |
| `icon_stat_mood` | 黄点 + 蓝块，看不出情绪 | 笑脸 / 上扬的嘴角 |

### 4.4 图标清单（23 个文件）

**道具 10 张**（`Art/Pixel/Icons/Items`，48×48）
`alarm_clock` `energy_drink` `exam_ticket` `headphones` `lucky_pen` `parent_note` `pencil_case` `sticker_star` `warm_tea` `wrong_book`

> 注意：这 13 张里 `time` 是时间显示用、`boss_alert` 是 Boss 警告，**都不是玩家属性**。
> 而内容体检列出的 13 个属性中，**「自主性」没有任何图标**（现有 12 张属性图只覆盖 11 个属性 + 时间）。

## 5. UI

### 5.1 面板九宫格（强制）

| 项 | 值 |
| --- | --- |
| 九宫格 border | **6px**（`panel_paper` 现状） |
| 最小可用尺寸 | 宽度 ≥ `2×6 + 32` = 44，高度同 |
| 大面板（> 400px） | 必须换大图，或用**纯色底 + `PixelPanel` 独立边框条** |

> **踩过的坑**：`panel_paper` 是 48×48、border 6、PPU 16。把它铺到 820×432 时，中间 36×36 区域被拉伸 **22 倍**，素材自带的纸纹横线被拉开后横贯整个面板（像素实测 `(193,173,131)` vs 背景 `(240,217,165)`）。**大面板一律用 `panel_paper_plain`（无纸纹）或纯色 + 独立边框。**

### 5.2 按钮状态（强制）

| 状态 | 说明 | 必需 |
| --- | --- | --- |
| normal | 默认 | ✅ |
| hover | 鼠标悬停 | ✅ |
| pressed | 按下 | ✅ |
| disabled | 不可用 | ✅ |
| selected | 当前选中（如已选地点） | ✅ |
| focus | 键盘/手柄导航焦点 | 建议 |

按钮文字由 `PixelButton` 统一样式，**不允许在外部用 `SetLabelFontSize()` 改字号**——`ApplyStyle()` 在 `OnEnable` 会刷回主题值。

### 5.3 格子状态（强制）

背包格、送礼格、卡牌槽统一四态：

| 状态 | 表现 |
| --- | --- |
| empty | 深棕底 `#342216`，无描边 |
| filled | 深棕底 + 图标 |
| selected | 暖金底 `#E2B24C` + 深棕描边 2px |
| locked | 底 × 45% 不透明 + 锁图标 |

> 格子的 `Button.transition` 必须设为 `Selectable.Transition.None`，否则 `ColorTint` 会把底色刷回白色（`InventoryPanelView:259` 已有先例）。

### 5.4 字号层级（强制）

| 用途 | 字号（1920 参考） |
| --- | ---: |
| 界面主标题 | 26 |
| 区块标题 / 详情名 | 24 |
| 正文 | 18 |
| 辅助信息 | 16 |
| 计数角标 | 14 |

**文字 rect 高度 ≥ 字号 × 1.6**。用 `VerticalWrapMode.Truncate` 时 rect 偏小会静默裁字，不报错。

## 6. 角色

### 6.1 行走帧（强制）

| 项 | 值 |
| --- | --- |
| 单帧尺寸 | **32×32**（与现有 `pink_player_down_*.png` 一致） |
| 每方向帧数 | **4 帧循环**（Idle 2 帧） |
| 方向 | 上 / 下 / 左 / 右（左向可由右向水平翻转，但需在 Animator 里显式处理） |
| 锚点 | **脚底中心**（`pivot = (0.5, 0)`） |
| PPU | 16 |
| 命名 | `{角色}_{动作}_{方向}_{序号}.png`，例 `pink_player_walk_down_0.png` |

> 锚点用脚底中心的原因：与场景里 `DecorSpec(x, y) = 底边中心` 的落点约定一致，避免角色悬空或陷地。

### 6.2 立绘（强制）

| 项 | 值 |
| --- | --- |
| 尺寸 | 512×512 或 256×256，全项目统一 |
| 背景 | 透明 |
| 用途 | 仅对话头像，不用于地图 |

**清理要求**：现有 24 张立绘，但游戏内 NPC 只有 3 个、Boss 3 个。未使用的立绘必须移到 `Art/_Archive/`，不得留在正式目录误导后续制作。

## 7. 场景

### 7.1 背景（强制）

| 用途 | 分辨率 |
| --- | --- |
| 全屏背景（过场/主菜单） | 1920×1080 |
| 房间底图 | 与房间画布一致（当前家四房间 1991×1184） |

禁止使用 640×360 这类小图放大铺满——放大后像素尺寸不统一。

### 7.2 瓦片（强制）

- **只能存在一套瓦片尺寸**。当前 `Modern_Interiors` 同时有 16×16 与 32×32 两套，必须二选一
- 建议选 **16×16**（与角色 32×32 形成 2:1，符合常见像素 RPG 比例）
- 瓦片 PPU 必须 16，且 Point + 无压缩

### 7.3 家具落点（强制）

- `DecorSpec(x, y)` 的 `(x, y)` 是**底边中心**，不是左下角
- 原因：Props sprite 的 pivot 是 `(0.5, 0.5)`，按左下角算会整体左移半个自身宽度（2026-10-19 实测左右两把椅子中心偏移 ±5.54 而设计值 ±4.6）

## 11. 制作管线（强制）

外部生成或放大的图**不得直接入库**，必须过门控：

```bash
python Tools/fix_pixel_art.py <图片或目录>              # 检测 + 脏图自动修复
python Tools/fix_pixel_art.py <路径> --downscale-clean  # CLEAN 图额外输出 1x 缩小版
```

三态处置：

| 结果 | 含义 | 处置 |
| --- | --- | --- |
| `CLEAN` | 本身就是真像素的整数放大（块不均匀 ≤0.5%） | 直接整数倍缩小，**不要**送修复器 |
| `FIXED` | 伪像素图已被重建为 1x 真像素（色数从数万坍缩到几千） | 可直接收货 |
| `REVIEW` | confidence=low，或修复后颜色不减反增 | **必须人工比对后再收**（颜色变多 = 误检信号） |

入库后按 §2.2 设置导入参数，再跑一次「缩到 24×24 是否可辨」的目视验收。

## 12. 验收清单

### 12.1 可机器检查（建议写脚本）
