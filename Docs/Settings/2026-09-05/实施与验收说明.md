## 存储与提交约定

运行路径为 `Application.persistentDataPath/Settings`，不改公司名或产品名。当前配置为 DefaultCompany / ML-project；未把推导出的 Windows 玩家目录当作实测证据。

- 正式：StudentGrowth.Settings.v2.json
- 临时：StudentGrowth.Settings.v2.tmp
- 备份：StudentGrowth.Settings.v2.bak
- 日志：StudentGrowth.Settings.v2.journal；journal.next 只是 journal 写入暂存文件
- 迁移快照：PlayerPrefs.original.json
- 损坏／诊断：Corrupted / Diagnostics

tmp 必须匹配 journal 的 operationId、generation、SHA-256，并处于 TemporaryValidated 或 ReplaceStarted，且代次严格高于有效正式文件和备份，才可恢复。普通 tmp 不晋升；已报告失败的 tmp 隔离。正式文件复读验证成功是提交点，后续 journal 清理失败不会把已提交操作报告成失败。无法判断替换是否完成时返回 Indeterminate，不虚报保存成功或确定失败。

持久化 DTO 使用 OptIn、字符串枚举、TypeNameHandling.None、InvariantCulture。UPM 版本 3.2.2，实际 Json.NET DLL 13.0.2。未知／整数枚举、必需顶层对象缺失、非有限数值均拒绝；缺失标量／可选对象按规则修复。高版本文件不写回。

仓库按当前单进程、单服务实例设计；未实现跨进程／云同步写入协调。未配置任何云同步。诊断留存暂不自动清理，以免删除用户数据；长期发布前应补充留存上限策略。

## 使用方式

进入 Play 后按 ESC 打开设置。音量滑杆立即预览；点击“应用”才接受并保存。“取消”恢复最近一次已应用设置并返回游戏；“恢复默认”只改变待提交值，还需点击应用。

有未应用修改时按 ESC／关闭按钮，菜单保持打开并提示选择应用或取消。保存失败显示“设置已应用，但尚未保存”，通过“重试保存”重试，不能重新提交当前预览。degraded 时禁用编辑与应用，提供“尝试恢复”，仍可关闭菜单。VSync 开启时帧率上限作为备用意图保存，选择框禁用。

旧的 AudioSettingsController.SetVolume 调用方保持可用：没有菜单编辑会话时执行独立事务；已有编辑会话时只更新预览。新增代码应优先通过 Service 的命令接口操作状态。

### 复现

Editor 停止 Play 后选择 `Tools > Student Growth > Verify Settings Transactions`。该入口运行选定普通 NUnit 方法并更新本目录结果，不保存用户场景。需要完整 Test Runner 回归时，先由用户自行处理未保存场景，再在 Test Runner 的 EditMode 中运行 Settings / Audio / PlayerMovementAudio 用例。

Play 隔离冒烟为开发工具：在工程 Temp 下建立 SettingsPlayVerification.request 后，Editor 会自动进入 Play、测试并退出；只能在没有进行其他 Play 调试时使用。active 标记由工具创建并在正常退出时清理；若进程异常终止，先核查该标记，避免后续 Editor Play 继续使用测试目录。Player 构建不包含这个条件分支。

主机复现需要 .NET 10 SDK 和项目当前 PackageCache：

```powershell
$env:DOTNET_CLI_HOME = "$PWD/Tools/SettingsP0a/.dotnet"
$env:DOTNET_GENERATE_ASPNET_CERTIFICATE = 'false'
dotnet restore Tools/SettingsVerification/SettingsVerification.csproj --configfile Tools/SettingsVerification/NuGet.Config
dotnet run --project Tools/SettingsVerification/SettingsVerification.csproj --no-restore
```

PackageCache 哈希目录变化时需更新工具的 DLL 引用，不能静默换用其他 Newtonsoft 版本。
