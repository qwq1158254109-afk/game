# 设置系统设计：ML-project 当前工程修订版

日期：2026-09-04。状态：设计修订交付，尚未实现；P0a 部分验证完成，发布门槛未通过。

## 1. 范围与版本关系

用户已确认实施对象为 `E:/unity/ML-project` 学生成长游戏，而非 TheCensor 打包游戏。

本稿替代《游戏内设置系统设计分析_第二次优化版》中面向当前工程的实施假设。原游戏的存档槽、截图、Steam 成就、I2 Localization 和 UserSettingsV1 不属于本期迁移对象。下载目录中的原文不修改。

授权范围为 P0a 技术验证、资源估算和设计修订，不代表批准实施 P0b/P1 或修改场景、资源、玩家设置。

首期估算基线：Windows 桌面、现有 Master/Music/SFX 三通道、窗口与无边框模式、配置可靠性及设置预览。多显示器选择、独占全屏、刷新率选择、语言资源、手柄重绑定列为待确认扩展，不默认承诺。

## 2. 当前工程基线与复用边界

| 已有组件 | 保留的职责 | 后续需要调整的边界，本次不实施 |
| --- | --- | --- |
| AudioSettingsModel | 三通道原始音量、范围处理 | 增加有限值检查；不得直接当作所有状态共用对象 |
| AudioSettingsController / IAudioSettingsProvider | 提供有效音量、VolumeChanged 事件 | 把运行时预览与 PlayerPrefs 写入分离，不能让 UI 预览调用旧的持久化路径 |
| AudioChannelSource | 音源基础音量乘以 Master 和对应通道 | 保持现有音量计算与订阅机制，不建立第二套音频 Manager |
| SettingsMenuController | Escape 入口、暂停、输入锁和恢复选中项 | 关闭流程增加未提交确认；F11 纳入同一显示事务入口 |
| SettingsPanelView / SettingsUiFactory | 现有三滑杆与外观 | 增加应用、取消、恢复默认和状态显示；保留已有引用 |
| GameplayInputGate | 游戏输入屏蔽 | 设置关闭、错误退出和场景切换时必须释放持有的锁 |

当前持久化来自 PlayerPrefs 三个键：`settings.audio.masterVolume`、`settings.audio.musicVolume`、`settings.audio.sfxVolume`。默认值均为 1，不采用参考游戏的 0.15/0.5。

当前 SetVolume 会更新模型并调用 PlayerPrefs.SetFloat；菜单 Close、应用暂停与退出会调用 Save。这是“即时修改、随后保存”的既有行为，不是预览。接入新语义时必须保留旧调用方兼容性并逐个检查调用点。

## 3. 状态、只读快照与操作所有权

| 状态 | 定义 |
| --- | --- |
| Defaults | 按本工程生成的安全默认偏好 |
| Persisted | 已确认正式文件提交成功的偏好快照 |
| AppliedPreferences | 已通过应用事务的用户偏好；不是显示硬件实际模式的同义词 |
| Pending | 本次编辑的偏好，不能被退出或后台回调自动提交 |
| ObservedRuntime | 可读取的当前有效音量和实际显示模式；无法确认时明确标为 Unknown |
| LastKnownGoodDisplayMode | 本次运行中经过验证、可用于恢复的实际显示模式 |

所有偏好快照深复制，嵌套引用互不共享。对外只提供不可变快照或防御性复制；不能直接暴露内部可变 DTO。比较偏好时排除 writeGeneration 等存储元数据。

只有 SettingsService 可以修改偏好状态。内部可以使用纯校验器、复制器和 Repository，不为每个 DTO 创建 MonoBehaviour 或全局单例。已有 AudioSettingsController 通过适配器参与新流程。

服务一次只允许一个应用、取消或恢复操作。显示协程由持久存在的协调器持有，不依附可关闭的面板。每次操作有 operationId，晚到的旧回调不能修改新状态。忙碌期间禁用重复应用/F11；退出或场景卸载请求必须经过统一取消/恢复流程。

## 4. 修订一：预览回滚与非显示事务

冻结为“只预览，点击应用才提交”。当前仅音频有真实 Applier；语言和可访问性未接入前不参与事务。

1. BeginEdit：深复制 AppliedPreferences 到 Pending，并记录所有可能参与预览的组件。
2. PreviewAudio：更新 Pending，并调用不写 PlayerPrefs、不写 JSON 的音频运行时接口；保持音量事件刷新。调用前就标记该 Applier 已触碰，即使它随后抛错。
3. Apply：首先校验完整 Pending，然后进入 NormalizingPreview。
4. 对本次所有已触碰的预览组件恢复旧 AppliedPreferences；不能只恢复“最后一次返回成功”的组件。
5. 若预览基线恢复失败，进入 Degraded，停止应用和自动写盘。
6. 基线恢复成功后，以旧 AppliedPreferences 的深复制为恢复快照，按固定顺序执行正式非显示 Apply。
7. 任一调用失败或抛错，恢复范围包括失败组件本身及此前已调用组件，按逆序执行。所有恢复都尝试执行，不因第一项失败就跳过其他恢复。
8. 全部恢复成功：AppliedPreferences 不变，Pending 保留用户输入，返回 Editing。存在无法恢复项：进入 Degraded，并把 ObservedRuntime 标为部分未知。
9. 全部应用成功：只提交非显示字段，不覆盖 Pending 中尚未确认的显示编辑。随后保存旧显示偏好与新非显示偏好的组合快照。

Cancel 同样恢复所有被预览触碰的组件；恢复成功后才丢弃 Pending。恢复失败不得显示“取消成功”。

未来加入语言 Applier 时，它必须可恢复旧语言，并把文本刷新与截图/磁盘 IO 分离。当前没有语言资源验证，不能声称此流程已在真实本地化系统通过。

## 5. 修订二：显示意图与实际模式

显示数据分为三种，不能用一个 DisplaySettingsData 同时表示：

- DisplayIntent：用户的偏好；持久化保存。首期字段为窗口模式、首选窗口宽高。显示器身份、独占模式与刷新率字段只在能力验证通过后启用。
- ResolvedDisplayMode：本次设备匹配和观察所得的实际模式，包括实际宽高、窗口模式、可用时的显示器身份/刷新率及观测可信度。
- LastKnownGoodDisplayMode：本次会话的可恢复实际快照，不使用已经不存在的硬件模式盲目回滚。

显示设备变化造成回退时，保留旧 DisplayIntent，同时更新 ResolvedDisplayMode 并提示降级。重新连接设备后可再次匹配原偏好，不因上次回退永久覆盖它。

玩家主动应用新显示意图：匹配、请求、等待、观察、确认后，才提交该意图。设备匹配发生降级时必须在确认页展示实际模式；不得把未实现的请求显示成已精确生效。

启动时以安全模式验证并建立本会话恢复点。没有用户确认历史时标记为 StartupSafe，而非伪称“玩家已确认”。无法恢复旧模式时依次尝试当前桌面模式、安全窗口；回退成功更新实际模式，原偏好不隐式改写。

F11 与设置页共用协调器，不允许直接绕过确认写 Screen 属性。安全的 VSync/帧率偏好单独作为 FramePacing 组；只有这些值变化时不触发黑屏保护倒计时。具体应用优先级在 P0a Unity 探针中验证。

显示请求只能在 Unity 主线程执行。等待帧数、观察超时、稳定次数、刷新率容差和焦点宽限是待设备实测的策略值，第二次优化版的 2 帧/2 秒/1.5 秒不是已经验证的保证。确认倒计时使用非缩放时间，后台恢复先处理待回滚操作再接受确认输入。

## 6. 修订三：组合事务结果

结果不是一个互斥枚举。建议契约（设计伪代码，非已实现接口）：

```text
DisplayTransactionResult
  OperationId
  RequestOutcome = Confirmed | Rejected | TimedOut | ApplyFailed | Cancelled
  RecoveryOutcome = NotNeeded | Restored | SafeFallback | Failed
  PersistenceOutcome = NotAttempted | Committed | NotCommitted | Indeterminate | ReadOnly
  RequestedIntent
  ActualMode + ObservationConfidence
  ErrorCodes[]
```

必须能表达：

- TimedOut + Restored + NotAttempted；
- Confirmed + NotNeeded + NotCommitted；
- ApplyFailed + SafeFallback + NotAttempted。

非显示组与显示组独立提交。非显示成功、显示失败时保留前者；UI 分组报告，不能只显示笼统“应用失败”。

保存失败不重复运行 Applier。重试写入最新 AppliedPreferences 快照，而非旧重试闭包，也不能把 Pending 显示预览带入写盘。

## 7. 修订四：tmp 提交语义，采用最小协议

本工程不采用“高代次 tmp 自动恢复”，也不为设置系统引入多文件 journal。正式文件的安全替换是唯一提交点；在提交点之前中断，允许丢失本次未确认持久化的偏好。

建议路径由 SettingsPathProvider 从本工程 persistentDataPath 生成：

```text
Settings/StudentGrowth.Settings.v1.json   正式配置
Settings/StudentGrowth.Settings.v1.bak    已验证的上一份正式配置
Settings/StudentGrowth.Settings.tmp      未提交暂存，永不自动晋升
Settings/Corrupted/                      有限保留的诊断副本
```

这是 ML-project 的新格式 v1，不是 TheCensor V1/V2。旧 PlayerPrefs 保留为只读导入来源，成功写入新配置前不宣布迁移完成；不删除原键，不双写。Editor 和打包 Player 的实际 PlayerPrefs/路径需分别验证，不能通过读写错误账户的注册表代替 Player 验证。

正常写入协议：

1. 同一服务串行写入；未来允许多游戏实例时须另加跨进程锁，当前不承诺并发写安全。
2. 深复制已提交偏好，验证有限值、版本和范围，生成下一代次。
3. 同目录写 tmp、Flush 并关闭、复读校验内容一致；到此仍不是提交。
4. 正式文件有效时用目标平台验证过的安全替换方式保留有效 bak；首次创建采用不覆盖已有目标的同目录 rename/move。无效正式文件不能轮换覆盖有效 bak。
5. 替换成功且复读确认一致：返回 Committed，更新 Persisted。
6. 确认尚未执行替换，或确认旧正式内容仍完好：返回 NotCommitted，保留 dirty。tmp 可留作诊断，但下次启动不能加载它。
7. 替换已经请求但无法确认磁盘结果：返回 Indeterminate，不谎报“肯定没有保存”，不立即用 bak 覆盖可能已经成功的新文件。
8. Indeterminate 状态先重新探测正式文件；验证新版本成功则收敛为 Committed，验证旧版本则可重试；无法确定则保留提示并禁止盲目轮换。

启动顺序：有效正式文件 → 有效 bak → 旧 PlayerPrefs（仅无可用新配置时）→ 默认值。所有 tmp 均作为未提交诊断候选，不比较代次决定加载。崩溃发生在替换前，恢复旧正式文件；替换后，恢复新正式文件。

schemaVersion 高于支持版本：保护原文件，只读兼容或使用会话默认值；状态标记 ReadOnly，后台/退出/重试都不得写回同一路径。

本次探针只证明 E 盘工作区在 .NET 10 主机上的同目录 move/replace 基本可用，尚未证明 Unity Player、persistentDataPath、掉电或文件系统故障下的耐久性。

## 8. 修订五：Degraded 状态与恢复接口

避免把业务阶段、运行时健康和磁盘状态混成一个枚举：

```text
SettingsStatus
  Phase = Idle | Editing | NormalizingPreview | Applying | ConfirmingDisplay | Recovering
  RuntimeHealth = Healthy | Degraded
  Persistence = Clean | Dirty | Indeterminate | ReadOnly
  BusyOperationId
  FailureDetails[]
```

对外契约必须有：GetStatus、GetReadOnlySnapshot、StateChanged、PreviewAudio、ApplyPendingAsync、CancelPendingAsync、TryRecoverRuntimeAsync、RetryPersistApplied，以及统一的取消请求。协程或项目已有异步设施均可，不为此新增第三方框架。

进入 Degraded：某组件恢复失败、实际运行时状态无法验证。旧 AppliedPreferences 保留为恢复目标，而不是宣称运行时仍等于旧值。

- 禁止新预览、应用和自动写盘，禁止把混合运行时状态保存为偏好。
- 保留错误信息和可用观测；UI 显示“未能完整恢复”，而非成功取消。
- TryRecoverRuntimeAsync 以最近提交偏好恢复非显示组件，以当前设备可用恢复点恢复显示，并逐项验证。
- 全部恢复成功才回 Healthy，Pending 从恢复目标重新建立；失败继续 Degraded。
- 提供重试恢复与退出/重启说明，但不自动重启游戏、不修改玩家进度。
- 面板被销毁不能掩盖故障；输入锁和 timeScale 必须由导航/生命周期清理保证释放。显示协调器仍负责收敛未完成事务。

单纯保存失败属于 Persistence=Dirty，不属于运行时 Degraded；不能因此禁用正常游戏。用户后续重新编辑时保留已应用偏好，仍提示尚未持久化。

## 9. 序列化与迁移约束

- 显式属性及 JsonProperty；固定 TypeNameHandling=None、字符串枚举、InvariantCulture。
- 顶层格式标识和 schemaVersion 必需；当前启用的 audio 对象必需。缺失/显式 null 均拒绝该候选文件，按恢复链处理。
- 对象内部可选字段缺失采用本工程默认值；未知字段同版本可忽略，高版本禁止写回。
- 未知枚举字符串及整数枚举均拒绝候选文件；不再使用“拒绝或修正”模糊表述。
- 浮点非有限值拒绝；有限的越界音量可夹取到 0～1 并记录修正。
- 深复制使用显式复制，不依赖序列化往返作为运行时常规复制方案。
- 当前代码并未证明公共字段必然不能序列化；属性式 DTO 是为了稳定、明确的契约，而非基于原 resolver 类名的推断。
- PlayerPrefs 导入按三键独立检查并校验；语言、语音、TheCensor IsFirst 不属于本工程迁移。
